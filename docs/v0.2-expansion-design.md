# DLP v0.2 expansion design

## Goal

Make the v0.1 downloader useful for both interactive users and scripts without
exposing yt-dlp's raw terminal stream. The existing terminal-first product and
in-process `yt_dlp.YoutubeDL` boundary stay intact.

## Product surface

- `dlp download URL...` and `dlp batch FILE` accept validated, scriptable
  settings overrides, `--dry-run`, `--json`, and `--no-prompt`.
- `dlp info URL` extracts sanitized metadata without downloading.
- `dlp history` lists or clears redacted completed, failed, blocked, and canceled
  jobs.
- `dlp profile list|show|save|delete` manages named settings snapshots in the
  per-user config directory.
- The TUI adds a profile selector, queue search, history, and a metadata preview
  while keeping the compact high-contrast layout and keyboard actions.

## Architecture

`Settings` remains the immutable-at-queue-boundary configuration snapshot.
`SettingsRepository` owns the primary TOML file; `ProfileRepository` stores
validated settings snapshots in a sibling `profiles/` directory; and
`HistoryRepository` appends redacted JSON records under the platform user-data
directory. History is bounded and never stores cookie contents, proxy
credentials, or URL query strings.

`DownloadEngine` gains an `extract_info` method and emits normalized progress.
`QueueRunner` marks every request terminal when cancellation occurs and records
results through an optional history sink. Dependency checks derive from the
effective settings and remain consent-based.

## Safety rules

The CLI and TUI share the same option compiler and advanced-argument guard.
Output, progress/logging ownership, URLs, command execution, credentials, and
configuration bypass remain controlled by DLP. User-visible errors pass through
the same colon- and equals-style redaction rules. Profile and history writes use
atomic replacement and user-only permissions where the platform supports them.

## Verification

Unit tests cover profiles, history redaction/retention, CLI parsing and JSON
output, metadata extraction, cancellation, dependency preflight, progress
clamping, and output paths after post-processing. Textual pilot tests cover
profile selection, queue filtering, history rendering, and the existing
dependency consent flow. Packaging tests launch the frozen macOS binary and
native Windows bundle, including the TUI import path that failed in v0.1.
